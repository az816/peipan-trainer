# 接线页性能验收报告

测试日期：2026-10-15。对应《终极重构执行方案》第五节的验收指标。

## 测试方法

- 浏览器：本机 Microsoft Edge（Chromium 内核），无头模式，用 playwright-core 驱动（只在本机临时安装，没有加进仓库依赖）。
- 手机环境：375 × 812、像素比 2、触屏、移动端模式；**CPU 降速 4 倍**，近似中端安卓手机。
- 触屏手势通过 Chrome DevTools 协议的 `Input.dispatchTouchEvent` 发出（真实的触摸事件序列，不是直接调函数）。
- 点击延迟用浏览器的 Event Timing（`PerformanceObserver` 的 `event` 条目），从输入到下一次绘制。
- 帧间隔用页面里的 `requestAnimationFrame` 记录。

> 这是模拟环境的结果，不是真机实测。真机（中端安卓 + iPhone）的数据还要补测，方法同上，可以用 Chrome 远程调试看 Performance 面板。

## 结果

| 指标 | 目标 | 结果 | 结论 |
|---|---|---|---|
| 点端子到出现反馈（53 次交互） | 75% ≤ 100ms，最差 ≤ 200ms | p75 48ms，最差 56ms | 通过 |
| 双指缩放过程中的帧间隔 | 不超过 50ms | p75 16.7ms，最差 50ms | 通过（最差一帧刚好 50ms） |
| 双指缩放结束后 | 相机层不再挂 `will-change` | `will-change: auto` | 通过 |
| 长按放大镜 + 拖动 | 不超过 50ms | p75 16.7ms，最差 16.8ms，放大镜正常出现 | 通过 |
| 时间继电器计时期间（星三角） | 帧率不低于静止时的 90%，每秒写存档 ≤ 1 次 | 58.8 fps / 静止 60.6 fps（97%），2 秒内写存档 0 次 | 通过 |
| 时间继电器计时期间的 DOM 改动 | 只更新 KT 自己 | 按下启动那一下各层更新一次；之后计时的 200ms 节拍里只有 KT 元件被重写（MutationObserver 统计） | 通过 |
| 循环切题 100 次 | DOM 节点数不变，内存回到基线 ±10% | 节点 1175 → 1175，事件监听 69 → 69，JS 堆 2.40MB → 2.57MB（+7.1%） | 通过 |
| 端子误选 | 0 | 每个端子正中点一下都选中它自己，误选 0；靠得太近时弹出“你点的是哪一个？” | 通过 |
| 动画红线 | `@keyframes` 和 `transition` 只出现 transform / opacity | 遍历全部样式表，违规 0 条 | 通过 |
| 页面脚本错误 | 0 | 0 | 通过 |

## 备注

- 方案里提到的“19 对端子热区重叠”是在完整题库（含 PLC、伺服等端子密集的题）上量的。新手路线只剩继电控制题，按旧的 14 单位热区算已经没有重叠的端子对；新的命中方式（网格索引找最近端子 + 屏幕上 44px 热区 + 太近就让人选）对端子密的情况同样有效。
- 系统设置了“减少动态效果”时，电流呼吸、端子闪烁、底部抽屉滑动都会关掉。
- 窗口被遮挡、某些内嵌浏览器不出帧时，画面更新有 150ms 的定时器兜底。
